Movie Recommendation

A movie recommendation program that runs in the terminal. Type one word such as “hantu” or “lucu”, the program guesses the closest genre, then shows the list of movies in that genre.

Project origin

The code started as a Codecademy assignment titled Recommendation Software, on the Movies topic. That assignment stopped at a program that already worked. I continued it to make it tidier: the data was moved into its own JSON file, the logic was tested with unit tests, and I built the web version.

Features

Search

  • Search by keyword. Type hantu and a horror genre suggestion appears along with its movie list, sorted by highest rating. If the keyword does not match, the program says so and suggests other words.
  • Search for a movie title by typing part of it. Behind the scenes, the program uses binary search on the sorted list to stay fast; when there is no match, the search falls back to going through items one by one (linear).

Recommendations and sorting

  • Marathon package. Enter a total duration limit, for example 240 minutes, then the program builds the combination of movies that comes closest to that limit.
  • See all the data with a choice of order: rating, year, duration, or title. There is a summary of the number of movies and the average rating per genre.

Managing data

  • Add movies, change ratings, and delete. The changes are written straight to the JSON file.

Data

All the data sits in one file, data_film.json, shared by the terminal version and the web version. So nothing is written twice. It holds 36 movies across 6 genres, 6 movies each: aksi, drama, komedi, horor, animasi, and dokumenter.

One thing worth explaining is the rating column. The numbers are my personal scores on a scale of 0 to 10, not IMDb ratings. The duration column is also still an estimate in minutes. Both can be changed from the data management view.

Algorithms

Part How it works
Genre suggestion Scoring in layers: genre name, keyword dictionary, then movie titles that contain the word. The results are sorted from the highest score.
Title search Binary search to find the start of the title, then scanned to the right as long as the prefix still matches.
Keyword search Linear search, matching the word in the title, year, and notes.
Marathon package Tries every combination of up to three movies, then takes the one whose total duration is closest to the limit. On a tie, the total rating wins.
Similar recommendations One genre, the smallest rating difference, then the closest year is preferred.

Web version

The web version is a single HTML page with Tailwind and JavaScript, no backend. It looks like a movie catalog: there is a search field, genre option cards, a table of movies, genre filters, a choice of order, the marathon package, and similar movie details that can be opened per row. The JavaScript logic was rewritten from the Python version so the result is the same. The web version is only for viewing data, while data changes are made through the terminal version.

Testing

There are 65 unit tests with unittest. They all test pure logic: input reading, genre scoring, binary search, sorting, and marathon combinations. One test class specifically reads the real data_film.json to make sure the data is healthy, from the number of movies, the completeness of columns, valid genres, unique titles, to the value ranges.

The test file is at test_film.py (opens in a new tab).

Bank Transaction Segmentation with Machine Learning

Clustering bank transactions into four groups with K-Means, then predicting the group label with Decision Tree and Random Forest. Final project of the Dicoding beginner machine learning course.

Question

Can bank transactions be grouped into clusters based on transaction behaviour (amount, channel, customer age, balance, and so on), and can those group labels be predicted by a classification model? This project answers both: first clustering, then classification.

Data

Data from a public Google Sheet referenced by the Dicoding course. One row is one transaction, not one customer. A single customer (AccountID) can have many transactions.

Feature Content

TransactionTypeDebit / Credit
LocationCity in the United States

CustomerAgeAccount holder age
CustomerOccupationDoctor, Engineer, Student, Retired

AgeGroupAge group

The raw dataset has 2,537 rows. After cleaning (handling missing values, categorical encoding, standardisation), 1,945 rows remain.

Method

  1. Load the data, inspect structure with shape, info, describe.
  2. Handle missing values, encode categorical features, standardise numeric features.
  3. K-Means: number of clusters chosen by Elbow Method based on Silhouette Score.
  4. Visualise clusters in 2D with PCA.
  5. Interpret four groups from aggregate (mean/min/max) of numeric features and mode of categorical features on inverse-transformed data.
  6. Classification: load clustered data, one-hot encode, 80/20 stratified split (1,556 train, 389 test).
  7. Decision Tree (random_state=42) and Random Forest (random_state=42).
  8. Tune Random Forest with GridSearchCV (5-fold, accuracy scoring).
  9. Evaluate: accuracy, precision, recall, F1 (macro). Save models with joblib.

Limitations

100% accuracy is not real-world prediction ability. The target being predicted is the K-Means cluster label (cluster ID), not a verified fraud label. The classification model only learns the segmentation pattern produced by clustering. This is a task of predicting a synthetic label, not detecting fraud.

A Silhouette Score of 0.4446 indicates moderate cluster separation, not very clear. The four transaction groups overlap on several features. The dataset is small (1,945 rows) and comes from course data, which may not represent real bank transaction distributions. The four groups are transaction groups, not unique customer segments. 100% accuracy on a small test set (389 rows) risks overfitting; it has not been tested on new data.
